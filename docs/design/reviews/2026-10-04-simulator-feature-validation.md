## Repairs

Review again.” The native passkey promise can resolve while iOS still reports `inactive`, before its foreground event. `AccountProvider.stepUp` now waits for that event before entering the signing callback. - **Private Friends:** authenticated owners can read their own network-filtered counts/lists without publishing their profile. New session-only routes derive the owner from the session and reject a different network. Anonymous lists retain their listing rules. Private query caches include the owner and have separate keys from public lists.

Unsupported Practice pairs explicitly identify AUSD/USDC as the supported choice.

Register it so the drawer retains its Card context. The confirmation sheet uses “Confirming…” while authentication and the operation run, rather than continuing to claim it is waiting for a passkey after authentication has completed (`51b1109`).
- **Declined receipt facts:** the receipt PDF's “Hold” row represented the requested amount even for a declined payment. Declines now label it “Requested hold”; the actual account had zero open holds (`dd540a4`).
- **Profile amount layout:** the large result amount overlapped the period controls on a public profile. Own and public profile result components now put the period controls below the amount (`6abf989`). Both layouts were subsequently inspected on the simulator without overlap.
- **Actual account follows route:** the Profile counts opened `account/follows.tsx`, which still used public-list visibility rules.
