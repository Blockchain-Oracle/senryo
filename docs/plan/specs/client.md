## Session policy (Mera bounty; enforced at the signer in packages/account)
- `getSigner()` wraps `toViemAccount(session)`; every `signTransaction` runs `Policy.evaluate()`: `value == 0` · `to` in allowlist · selector allowlisted (`decodeFunctionData`) · notional + leverage **decoded from calldata** · caps derived from market OI cap and account balance · session-total and per-minute caps · reduce-only actions uncapped · withdraw to own EOA = in scope (D-039); other destinations = step-up.
- `signMessage` only our formats (`Senryo:claim:`, `Senryo:push:`, SIWE with nonce + expiry). `signTypedData` in session only for our own domains (claim, voucher, trigger); Perpl key enrolment, Aurora intents, AUSD 3009, spend allowance, 7702 = step-up.
- Expiry `min(startedAt + TTL, lastUsedAt + IDLE)` (30 / 5 min defaults); lock on AppState `background` (privacy plate on `inactive`); web: `visibilitychange` idle, `pagehide` lock, BroadcastChannel sync across tabs.
- Step-up = fresh passkey ceremony pinned to the stored credential → one-shot session → `end()` in `finally`.
- Face ID per trade (D-037): practice OFF; mainnet ON above `FACE_ID_TRADE_THRESHOLD_USD`; native = SecureStore biometric read; web = passkey assertion.
- One promise-chain queue per address (ordered nonces). Chip: `● TRADING UNLOCKED · 24:10` / `● LOCKS IN 0:59` / `○ LOCKED · FACE ID TO TRADE`.

## Data flow
Sources: Perpl context/WS · our API WS (engine marks, session, account deltas) · Monad `monadLogs`/`monadNewHeads` for user events (commit states) · viem reads at `finalized` for buckets, `latest` for optimistic display · Envio via our API for history · Aurora REST polled while a deposit is in flight.
Query keys (`query/keys.ts`): `config`, `markets.list`, `market.{ctx,candles,session}`, `account.{buckets,equity,positions,orders,activity,gas}`, `perpl.account`, `card.{summary,auths}`, `fund.{address,deposits,exec}`, `starter.status`, `prefs`. Invalidate `['account', addr]` on finalized user events. Persist markets/buckets/positions/card.summary (24 h) — shown as stale until refetched.
`PriceStore`: socket writes to a buffer; one rAF flush per frame; charts read shared values (no React renders); hero ≤ 4 Hz, watchlist rows 1 Hz visible-only; stale after `PRICE_STALE_MS`.
Lifecycle: submitted (journal) → proposed (PENDING row; buckets untouched) → voted ("FILLED", haptic + sound) → finalized (invalidate, clear journal) · abandoned/reverted → roll back + warning. `TxRecovery` reconciles journal on launch; never resends.

## Performance targets
Cold start < 1.2 s with cache · charts 60–120 fps · Face ID → sent < 700 ms (pre-simulate during hold) · web landing ≤ 120 KB gz, trade route ≤ 250 KB · ≤ 1 Perpl WS + 1 engine WS + 1 chain WS · PBKDF2 derivation measured (quick-crypto if > 150 ms).

## iOS feel
Haptic map: tick (selection) · press (light) · snap (rigid) · confirm (soft) · filled (success) · warn · fail (error + 8 px shake, never on cancel) · liquidation (error + heavy). Sounds (expo-audio pool, `playsInSilentMode: false`, mixWithOthers, toggle): fill, deposit, send, unlock, liquidation; optional error off by default. Live Activities: Order, Deposit, Watch (≤ 8 h, P&L as %), `MIN_UPDATE_MS`. Widgets: Portfolio, Watchlist. Push channels: fills, liquidation (time-sensitive), deposits, card, price alerts. Motion: `bezier(0.2,0,0,1)` 120/160/200 ms, no overshoot except sheets. Dynamic Type caps, reduced motion/transparency, VoiceOver labels, 44 pt targets, deep links on the rpId host with chainId.
