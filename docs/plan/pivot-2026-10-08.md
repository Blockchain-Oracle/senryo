**Pricing, positions and money safety**
- **D-259 One price source: Pyth Core.**
  - The chart and settlement use the same feed.
  - Settlement uses `parsePriceFeedUpdatesUnique` over `[T, T+5s]`; a missing print means void and refund; fee is 0.
  - Receivers: testnet `0xFC6bd9F9f0c6481c6Af3A7Eb46b296A5B85ed379`; mainnet decided by testing a keyed payload against `0xB754BA51…508d` and `0x2880aB15…7B43`.
  - Coinbase WebSocket is a labelled display fallback for crypto only.
- **D-260 Shared pool (user's choice).**
  - Testnet: filled with Test USD.
  - Mainnet: a small seed the user funds (the only real-money wait). Caps mean the pool can never lose more than it holds.
  - Anyone can supply later ("Earn"), priced at settled epochs.
- **D-261 Commit, then fill at the next print** (Codex review).
  - A tap commits the signed call on chain: stake escrowed, target = commit + 1 s.
  - It fills at the unique print in `[target, target+5s]`. Finalising is permissionless; no print means a refund; no discretionary cancel.
  - Close works the same way, after ≥ 3 s held and a newer print.
  - Opens and closes stop at expiry − 20 s.
  - Fills land in about 2 s, behind an optimistic "Opening…". Live PnL is labelled "cash-out ≈ $x".
- **D-262 Pricing.**
  - Band probability `Φ(ln(H/S)/v) − Φ(ln(L/S)/v)`, `v = σ√τ`.
  - Clock: calendar for crypto, session for equities.
  - σ per feed in a versioned, bounded config.
  - Half-spread 2 pp plus a bounded inventory surcharge.
  - Outside 3–97% is **refused, never clamped**. Payouts floor, debits ceil.
- **D-263 One position shape: a fixed band around the open K.**
  - Up (K, ∞) and Down (0, K) refund at exactly K.
  - Range [K−a, K+b] is inclusive.
  - Moonshot (K+x, ∞) excludes its strike.
  - Offsets come from a fixed menu per feed.
  - The original stake basis is kept through partial closes.
- **D-264 Solvency by full reservation.**
  - Every open ticket reserves payout − stake.
  - Invariant: **vault USDC ≥ unpaid credits + Σ reserved**, rechecked after every open, close and settle.
  - Payouts land automatically: `claimFor` batches of 32, settle batches of 8, split above 5M gas. They show "pending" until the receipt; failed recipients keep a claimable credit.
- **D-265 Stocks follow the calendar.**
  - Reuse `contracts/src/oracle/MarketCalendar.sol` (kept).
  - A window can't cross the close, a holiday or an early close.
  - Agari halt rule: confidence > 50 bps or older than 15 s.
  - The app shows "Opens 9:30 ET".

**Accounts and signing**
- **D-266 Gasless by signature.**
  - Every action is an EIP-712 intent: action, owner, window, band, amount, minimum shares, recipient, config version, deadline, epoch.
  - Unordered owner nonces, which can be cancelled.
  - Relayed by the journaled sender (`packages/chain/src/send.ts`), with an exact-calldata simulation before submitting. About $0.001 per call.
  - External wallets sign the same intents.
  - Replaces StarterDrip MON drips and `topup.ts`.
  - Finite allowances only.
- **D-267 Enforceable session.**
  - One Face ID (Mera) signs a `SessionGrant`: ephemeral delegate key, cap per call and per session, expiry, epoch. The contract enforces the caps and the owner key is zeroed.
  - Real: $25 per call, $100 per session, 15 min. Practice: $1,000 / $10,000 / 60 min.
  - Withdraw, send and grant changes always need the owner's Face ID.
  - In the app: evaluate → reserve budget → sign.

**Engineering and distribution**
- **D-268 One market catalogue** (`packages/config/src/catalog.ts`): symbol, Pyth id, kind, σ, cadences, calendar, mark, band menu. It feeds the deploy, keeper, indexer, API and apps.
- **D-269 The web is a full app.**

  - Passkey sign-in first. "Use a wallet" through **Reown AppKit** `@reown/appkit@1.8.24` + wagmi adapter (MetaMask, Rabby, Backpack, OKX, Coinbase; Phantom left Monad). The viem-only invariant allows that one module.

- **D-270 One native build (0.4.0), cut early, then over-the-air only.**

  - It's cut right after S1 (S1b) with a frozen native set (Ramp and victory-native removed), so App and Play review run in parallel with the contract and services stages.

## Architecture

**Contracts** (`contracts/src/markets/`; Foundry, solc 0.8.31, `evm_version = "osaka"`, OpenZeppelin 5, ≤ 400 lines per file)

Mostly ported from crypto-world-fair (CWF), each file with a `Ported from CWF d7b576b:<path>` header.

- **`Windows.sol`**, from CWF `engine/libs/{AdminLib,ResolveLib,PrintLib,Grid}.sol`, `EngineTypes/Errors/Storage` and `interfaces/IPrintVerifier.sol`, without the order book (`MatchLib`/`BookLib`/positions).
  - Series and append-only **policy versions**, each bound to an immutable verifier.
  - `openWindow` (keeper or lazily), permissionless `recordPrint` (first valid print wins), `copyOpenFromPrev` for back-to-back windows.
  - **No calls before the open print exists.**
  - Optional cross-check source → void when the gap exceeds 25 bps; permissionless `voidExpired`; no admin void.
  - Changes from CWF: a tie or void **refunds** (CWF pays half face); source id 1 (Pyth) allowed; `recordPrint` is payable and forwards the Pyth fee.
- **`PythPrintVerifier.sol`** (implements `IPrintVerifier`) wraps `contracts/src/predictions/PythBoundaryOracle.sol`.
  - `parsePriceFeedUpdatesUnique` over `[T, T+grace]`.
  - Max confidence 25 bps crypto, 50 bps equities.
- **`BandReserve.sol` + `BandPricing.sol`**, from CWF `products/range/{RangeReserve,RangePricing,RangeMath}.sol`, `products/shared/Payouts.sol` and `fair/FairValue.sol` (Φ table, `lnWad`, `bandProbE6`, `floorStake`).
  - Kept from CWF: full reservation; pay-or-owe; refusal outside the odds band.
  - Caps added from CWF: **total exposure ≤ 60% of the pool**, and **a per-expiry cap** (`lockedByExpiry ≤ maxExpiryLocked`), because all calls ending at the same second are decided by one print.
  - Added for Senryo:
    - commit → finalize at the unique print (D-261);
    - close / cash-out;
    - supplier entry and exit only at **settled epochs** (CWF's Range let suppliers leave after a losing close print);
    - automatic `claimFor`;
    - spot taken from the fill print, never a caller-chosen "latest".
  - The strike K is the **window's open print** (one shared line for everyone in the window), as in Owarine and CWF.
- **`SessionGrants.sol`**: CWF `IEventVault` grant caps (per call, per day, open positions, maximum price, market scope, budget, expiry) plus a new **EIP-712 `placeForBySig`** (unordered nonces, deadline, epoch). CWF only accepted `msg.sender == actor`.
- **`FeedRegistry`** (inside Windows policies) + `MarketCalendar.sol` (kept).
- `testnet/TestUSD.sol` (6 decimals, permit + EIP-3009, `MINTER` for the sponsor).
- **Tests:** port CWF `test/engine/{Prints,Resolve,Roller,Admin,OpenPrintGate}.t.sol`, `test/products/range/*` and the invariant handlers.
  - Replace the Tempo TIP-20 fixture with an OpenZeppelin ERC20 mock and a blacklist mock.
  - Remove the TIP-403 receive-policy checks; pay-or-owe still uses `trySafeTransfer`.
- **Not ported from CWF:**
  - the order-book engine, `MarketMakerVault`, Tempo wallet/keychain code, RedStone and Data Streams verifiers;
  - Yosuku-derived designs (`EventVault`, `ParlayReserve`, `LeverageReserve` and `PrivateDesk` lineage): for these we reimplement the behaviour only.
- **Deleted:** `SenryoBinaryV1` and `BinaryMath` (never deployed; constant-product odds ignore spot).
- **Monad specifics:**
  - `latest` is only *proposed*, so cursors, settlement and money reads use `finalized`;
  - explicit gas limits (the limit is what's charged);
  - 300 ms blocks; 1 s timestamp granularity.

**Services** (Coolify; the key is server-side only)
- api:
  - `prices/`: the `PythGateway` plus `/v1/prices/{recent,candles}`. Fan-out is described under "Stack and performance". Owarine's `coalesce`/`spot-sse` are the starting point, changed to one coalescer per feed and frames serialised once.
  - `relay/`: simulate → submit → journal; rate limit per address; boundary prints archived independently.
  - `starter/`: grant Test USD once.
  - `proof/`.
  - Kept: `auth`, `profiles/handles`, `notifications`.
- **One multiplexed `/v1/stream`** (CWF `http/stream.ts` pattern) carries prices **and** the user's own topics (fills, results, payouts):
  - an HMAC ticket for user topics;
  - a 15 s ping carrying **server time** (the countdown offset);
  - `Last-Event-ID` replay after a reconnect.
  - So there is one connection per app.
- `relay/` follows CWF's relay checklist (`packages/markets/src/relay/{engine,gates,ledger,validator}.ts`):
  1. chain id;
  2. target and selector allow-list;
  3. no max approvals;
  4. per-area gas cap;
  5. deadline;
  6. per-device budget;
  7. exact-calldata simulation before submitting.
- keeper: `finalize`, `settle`, `payouts`, `void-stale` and `pushes`.
  - Decision modules ported from CWF `services/ops/src/actors/{window-roller/plan,settler/decide,price-relay/slots,halt-watch/decide,seed-maker/fair}` and its `runtime/*`, with RedStone replaced by Hermes.

## Stack and performance (binding: D-272; every choice read through Context7, raw notes in the scratchpad `arch/` → `docs/research/pivot/architecture.md` in S0)

**Pyth key economics**
- The Starter plan is crypto-only, updates **at most once per second**, and says "Redistribution: Not permitted". Equities need Pro.
- So the chart breathes through **client easing**, not tick rate.
- We serve display values plus boundary bytes that are already on chain, **never raw Pyth payloads**.
- The key lives in **one place: the API's `PythGateway`**. The keeper, relay, CRE and Proof all read the `pyth_prints` archive. The keeper's key copy is break-glass only, used once when no archive row exists by T+10 s.

- **Chart:** ≤ 2 ms per frame at 60/120 fps; first line ≤ 300 ms after `/recent`.
- **Calls:**
  - tap to "Opening…" ≤ 100 ms;
  - POST to receipt p50 ≤ 1.5 s;
  - tap to fill p50 ≤ 3 s;
  - payout ≤ boundary + 10 s.
- **Web (Lighthouse mobile, median of 3):** LCP ≤ 2.5 s, TBT ≤ 200 ms, CLS ≤ 0.05; first-load JS ≤ 120 KB on `/` and ≤ 220 KB on `/app`.
- **Hermes:** about 2–10k calls a day (ceiling 86,400). **RPC:** about 70k calls a day (about 0.8 rps); clients 0.
- **Memory on `agari-box`:** api 256 MiB · keeper 160 · shared Postgres 384 · Envio 512 · Hasura, Redis and web Node 0 → **≈ 1.3 GiB**, down from 2.8.
