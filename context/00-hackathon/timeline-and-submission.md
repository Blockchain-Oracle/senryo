## Submission checklist (official requirements only)
**Repository** (rules §4.1; track pages)
- [ ] Public GitHub repo, accessible to `metropolis@hackathon.monad.xyz`, and it stays public after the event
- [ ] OSI-style open source license (MIT / Apache 2.0 / GPL…)
- [ ] README: setup instructions, **attribution of external code**, **pre-existing components identified**, **AI coding tools disclosed**
- [ ] Docs: project description, architecture overview, tech stack, setup/deployment
- [ ] Commit history covering the build window

**Monad**
- [ ] Deployed to Monad mainnet or testnet
- [ ] Explanation of how the project uses Monad, plus contract addresses / transaction hashes

**Media** (track pages)
- [ ] Logo/graphic (JPG/PNG/WEBP, ≤3 MB)
- [ ] Technical demo video, ≤3 min, showing the **live working product** (not slides or code)
- [ ] Pitch video, ≤2 min: team, problem, why you
- [ ] Live product link + access instructions + test logins for judges
- [ ] Optional: ≤30 s product ad (not judged)

**Bounties**
- [ ] For each bounty you add, complete its extra fields (e.g. Kuru Consumer asks for *Target users* and *Evidence of demand*; Dynamic wants a ≤3-min demo link of the Dynamic flow). See [prizes-and-bounties.md](prizes-and-bounties.md)
- [ ] Only add bounties marked **All tracks** or tied to **your** track

**Portal**
- [ ] Profile complete, team created (before **6 Oct**), project created (this unlocks the submission checklist, still unseen)
- [ ] Post **Progress Updates** in the Project tab (the portal has a section for them)

*The live submission form was locked in the capture until a project exists. Re-check the checklist once the project is created.*
