# ack3 — AI Security Scan (+ Wake) and security checklist before submitting

> Researched 2026-09-28 from ack3.ai/llms.txt, ack3.ai/research/*.md (including the Metropolis sponsorship post of 1 Sep 2026), and github.com/ack3-ai/wake. Also covers Blockaid, Safe and Foundry/Hardhat testing tips.

## Overview: what ack3 is
- **ack3 (ACK3 LTD)** is an "AI-native web3 cybersecurity company". Its **team built Ackee Blockchain**, which has audited Ethereum and Solana protocols since 2021 (Lido, Aave, Monad, Safe, Axelar). The team reports **237 audits with 0 hacks**.
  - Founder: Josef Gattermayer, Ph.D.
  - AI tooling partner: **Michal Převrátil**, author and lead developer of Wake.
- **Services:** deep security reviews combining manual review, **Wake** fuzzing and the **ack3 AI scan**. Scope covers EVM contracts, Solana programs and offchain infrastructure.
- **ack3 AI scan.** Their AI auditor.
  - Claimed "+30% bugs found vs bare frontier models" (recall on 94 real high-severity bugs from public audit contests, May 2026 run).
  - It runs inside every ack3 manual audit and **in Sherlock's Audit Engine** (launch partner, 18 Aug 2026). Auditors validate its findings.
  - **It is not a self-serve SaaS.** There is no public "upload your repo" UI. Engagements go through https://ack3.ai/contact. (Not found: an API or CLI for the AI scan.)
- **Wake** (open source, ISC license): a Python/pytest-based Solidity testing framework with a **fuzzer** (property-based and Manually Guided Fuzzing), **vulnerability detectors**, printers, an LSP, and the "Solidity (Wake)" VS Code extension. This is the part you can use yourself today.

## Quickstart: Wake on a Monad project

```bash
# Python 3.10+ for Wake 5 RC; stable Wake 4 works on 3.8+. Apple Silicon needs Rosetta.
pip3 install eth-wake            # Wake 4.22.x (stable)
# pip3 install --pre eth-wake    # Wake 5.0.0rc3 (docs: https://ack3.ai/wake/docs/5.0.0rc3/)

wake up          # initialise config / compile in an existing Foundry or Hardhat repo (see docs)
wake detect all  # run every vulnerability and code-quality detector
wake detect <detector-name>
wake print <printer-name>   # e.g. dump inheritance, call graphs, storage layout
```

**Fuzz test (Python).** It runs against Anvil, which you can run with Monad execution: `anvil --network monad`.
```python
# tests/test_vault_fuzz.py
from wake.testing import *
from wake.testing.fuzzing import *
from pytypes.src.Vault import Vault          # generated by `wake up pytypes`

class VaultFuzz(FuzzTest):
    def pre_sequence(self) -> None:
        self.vault = Vault.deploy()
        self.deposits = {}

    @flow()
    def deposit(self) -> None:
        user = random_account()
        amt = random_int(1, 10**20)
        self.vault.deposit(value=amt, from_=user)
        self.deposits[user] = self.deposits.get(user, 0) + amt

    @flow()
    def withdraw(self) -> None:
        user = random_account()
        bal = self.deposits.get(user, 0)
        with may_revert() as e:
            self.vault.withdraw(bal, from_=user)
        if e.value is None:
            self.deposits[user] = 0

    @invariant(period=10)
    def solvency(self) -> None:
        assert self.vault.balance >= sum(self.deposits.values())

@chain.connect()
def test_vault_fuzz():
    VaultFuzz().run(sequences_count=30, flows_count=100)
```
```bash
wake up pytypes && wake test tests/test_vault_fuzz.py
```

- Wake API names above follow the Wake 4 README (`FuzzTest`, `@flow`, `@invariant`, `may_revert`, `chain.connect`). `random_account`/`random_int` and `from_=` come from the Wake docs; **check them against your installed version**, especially on Wake 5.
- CI: GitHub Actions `wake-setup` and `wake-detect` exist on the Marketplace.
- ack3 research articles give worked examples: reentrancy variants (ERC-721/777/1155, cross-function, read-only), proxy testing, EIP-712 signing and differential fuzzing.

## Pre-submission security checklist (Monad-specific)
1. `forge test --network monad` (Foundry ≥ v1.8) so tests use Monad gas pricing and the **128 KB contract / 256 KB initcode** limits.
2. Invariant or fuzz tests on money-moving paths (Foundry `invariant_*` or Wake).
3. `wake detect all` and/or Slither. Fix or document every finding.
4. Reentrancy on every external call (CEI + `ReentrancyGuard`). Check ERC-721/1155/777 hooks.
5. Access control on admin functions; move ownership to a **Safe** multisig (below).
6. Signature replay: EIP-712 domain with `chainId` 143, nonces, deadlines.
7. Oracle freshness and staleness checks. Monad blocks are ~300–400 ms, so `block.timestamp`-based logic has coarse resolution. Don't assume one tx per block.
8. Don't rely on the `latest` tag for settlement offchain. Use `finalized`.
9. Verify contracts on MonadVision/Monadscan (Sourcify or Etherscan v2 with `chainid=143`) so reviewers and scanners can read the source.
10. A README "Security" section: scope, assumptions, known issues, test commands. ack3's checklist wants the project to be compilable, frozen, documented (NatSpec), tested, and statically analysed.

## Related tools (brief)

### Foundry and Hardhat on Monad
- **Foundry v1.8+ has first-class Monad support.** Set `network = "monad"` in `foundry.toml` or pass `--network monad`.
  - Local default hardfork is `MonadTen`, but mainnet runs `MONAD_NINE` per the network info page (v0.15.2). To reproduce mainnet locally, set `hardfork = "monad:MonadNine"`.
  - Forks of mainnet or testnet auto-select the hardfork.
  - `anvil --network monad` runs locally; `anvil --fork-url https://rpc.monad.xyz` forks mainnet.
  - Migrate off the legacy `category-labs/foundry` fork (`anvil --monad`, `foundryup --network monad`).
- **Hardhat 3** (Node ≥ 22.13): `git clone https://github.com/monad-developers/hardhat3-monad`. Existing projects need `solidity 0.8.31` with **`evmVersion: "osaka"`** (required for Monad) and Hardhat ≥ 3.1.0. Networks: `monadTestnet` at `https://testnet-rpc.monad.xyz` (10143) and `monadMainnet` at `https://rpc.monad.xyz` (143).
- CI: `foundry-rs/foundry-toolchain@v1` with `version: v1.8.0`, then `forge test --network monad -vvv`.

### Safe multisig on Monad
- Safe is supported. Use https://app.safe.global. Contract addresses are at https://github.com/monad-crypto/protocols/blob/main/mainnet/safe.jsonc.
- `safe-tx-hashes-util` (https://github.com/pcaversaccio/safe-tx-hashes-util) supports Monad for independently verifying Safe tx hashes before signing.
- Transfer `owner` or admin roles to a 2-of-3 Safe before demo day, and mention it in the README.

### Blockaid
- A real-time detection platform for transaction and token scanning, dApp and address screening, and onchain monitoring. It is listed in Monad docs under Analytics ("real-time detection platform for on-chain monitoring and fraud prevention").
- **Monad support in its scanning APIs is unverified.** Blockaid publicly names Ethereum plus six or more EVM chains, and new chains are added by announcement. Docs are at https://docs.blockaid.io (a JS app; llms.txt unavailable). Access is B2B through sales, so it is unlikely to be usable in a hackathon without contact.

## Gotchas
- The ack3 AI scan is **post-selection and not self-serve**. Don't promise "audited by ack3" in the submission.
- Wake needs Python and compiles with its own solc manager. Point it at your Foundry remappings; run `wake up` first.
- Wake 5 is an RC with a migration guide. For a six-week hackathon, stable Wake 4 is safer.
- Apple Silicon: the Wake README says Rosetta must be enabled.
